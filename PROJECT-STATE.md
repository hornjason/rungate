**Session 2026-11-03 session 76 (the reviewer could not read an environment variable — ai-review's UNMEASURED rate, diagnosed and fixed):**
- ROOT CAUSE OF THE ai-review UNMEASURED RATE, FOUND AND FIXED (#1733, merged 9fbfba92). `buildReviewPrompt()` told the reviewer five times to read a path out of an environment variable. `AI_REVIEW_ALLOWED_TOOLS` is `Read,Grep,Glob,Write` and not one of those four returns the value of an environment variable, so the instruction was unfollowable and the agent answered it by guessing from a directory listing. On the captured run it wrote a well-formed payload to `_temp/ai-review-findings-<nonce>.json` while the workflow read `_temp/ai-review-findings-<nonce>.d/ai-review-findings.json` — one path segment apart, 37 turns of a budget of 80, `is_error:false`, no permission denial.
- WHY FOUR OF THE FIVE NEVER SHOWED A SYMPTOM, which is why the fix is five and not one: the four INPUT paths name files that already exist, so `Glob` finds them and the variable is never needed — they worked BY ACCIDENT. The OUTPUT path does not exist yet, so there is nothing to glob and the name has to be invented. A guess is right only sometimes, and that is the whole of the intermittency. Repairing only the one with a symptom would have left four live instances, each silently glob-dependent.
